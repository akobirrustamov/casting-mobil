## 1. Что за проект

Мобильный сервис потокового видео по подписке (аналог Netflix) для рынка Узбекистана.
Пользователь оформляет подписку и получает доступ к каталогу фильмов и сериалов.
Видео хранится и раздаётся через **Bunny Stream**, наш бэкенд видео не отдаёт — он
только проверяет право доступа и выдаёт временную подписанную ссылку.

**Ключевой принцип архитектуры:** сервер — это турникет, а не труба.
Ни один байт видео не проходит через наш VPS. Загрузка идёт напрямую с админки
в Bunny, просмотр — напрямую с CDN Bunny на устройство.

## 3. Жёсткие правила для кода

Эти правила не обсуждаются, соблюдай их всегда.

### Общее
- Только **production-ready** код. Никаких `// TODO: доделать`, заглушек и псевдокода.
- **Разбивай на компоненты и классы.** Один класс = одна ответственность.
  Не пиши всё в одном файле, не создавай «god service».
- Не переписывай файл целиком, если нужно поменять три строки.
  Показывай изменения в формате **ДО / ПОСЛЕ** с пояснением причины.
- Комментарии в коде — на русском, по делу, только там где логика неочевидна.

### REST API
- Используем **только** `GET`, `POST`, `PUT`, `DELETE`.
- **`PATCH` не использовать никогда.** Частичное обновление делаем через `PUT`
  с полным телом ресурса.
- Все ответы — DTO (Java `record`), никогда не отдаём JPA-сущности наружу.
- Ошибки — через `@RestControllerAdvice`, единый формат:
  ```json
  { "code": "SUBSCRIPTION_REQUIRED", "message": "Требуется активная подписка" }
  ```
- Валидация входа — `jakarta.validation` аннотации на DTO.

### Безопасность
- Секреты (`BUNNY_API_KEY`, `BUNNY_TOKEN_KEY`, JWT-секрет, пароль БД) —
  **только** через переменные окружения. В `application.yml` — плейсхолдеры
  вида `${BUNNY_API_KEY}`. Ни одного секрета в git.
- Прямые ссылки на видеофайлы клиенту не отдаются **никогда**.
  Только подписанный URL с ограниченным временем жизни.
- Права доступа проверяются на бэкенде, а не на клиенте.

### UI
- Современный, живой интерфейс: анимации, градиенты, hover-эффекты,
  скелетоны при загрузке. Никаких шаблонных бутстрап-форм.
- Мобильное приложение — тёмная тема по умолчанию (это видеосервис).
- Все состояния экрана обрабатываются: загрузка, пустой список, ошибка сети,
  «нужна подписка».

## 4. Как ты общаешься с разработчиком

Разработчик впервые работает с видеостримингом. Поэтому:

1. **Объясняй новые термины сразу в скобках.**
   Пример: «нужен вебхук (это когда внешний сервис сам стучится к нам на URL)».
2. **Не делай длинных вступлений.** Сразу к делу.
3. **Разделяй зоны ответственности явно.** В каждом шаге отмечай:
   - 🤖 `[КОД]` — то, что пишешь ты
   - 👤 `[РАЗРАБОТЧИК]` — то, что человек делает руками (дашборды, ключи, оплата, тесты)
4. **Останавливайся на ручных шагах.** Если для продолжения нужно, чтобы
   разработчик что-то сделал в дашборде Bunny или добавил переменную окружения —
   выведи блок:
   ```
   ⏸ СТОП — нужно твоё действие
   1. Зайди на dash.bunny.net → Stream → ...
   2. Скопируй значение X
   3. Добавь в .env строку BUNNY_X=...
   Напиши "готово", когда сделаешь.
   ```
   И **не пиши код дальше**, пока не получишь подтверждение.
5. **После каждого шага говори, как это проверить.** Конкретную команду curl,
   конкретный экран, конкретный ожидаемый результат.

## 5. Архитектура: поток данных

### Загрузка видео (админ)
```
Админка ──1── POST /api/admin/videos/upload-ticket ──► Spring Boot
                                                          │
                                                          ├─ создаёт video-объект в Bunny
                                                          ├─ сохраняет строку в PostgreSQL
                                                          └─ считает SHA256-подпись
Админка ◄─2── { videoId, signature, expiration } ─────────┘
   │
   └─3── TUS upload (файл напрямую) ──────────────────► Bunny Stream
                                                          │
                                                          ├─ транскодинг в 4 качества
                                                          ├─ нарезка HLS
                                                          └─ репликация по регионам
Spring Boot ◄─4── POST /api/webhooks/bunny (status=3) ─────┘
   └─ помечает видео как READY
```

### Просмотр (подписчик)
```
Телефон ──1── GET /api/videos/{id}/playback ──► Spring Boot
                                                   ├─ подписка активна?
                                                   ├─ план покрывает контент?
                                                   ├─ лимит устройств не превышен?
                                                   └─ HMAC-SHA256 подпись URL
Телефон ◄─2── { hlsUrl, expiresAt } ───────────────┘
   │
   └─3── GET playlist.m3u8 + сегменты ──────────► Bunny CDN
                                                   └─ проверяет токен, отдаёт видео
```

## 6. Важные технические детали Bunny Stream

Эти вещи легко сделать неправильно — держи их в голове.

1. **Директорийный токен обязателен.** HLS — это манифест плюс сотни сегментов.
   Подпись на конкретный файл откроет только манифест, сегменты вернут 403.
   Подписывать нужно с `isDirectory = true` и `tokenPath = "/{videoId}/"`.
   При `isDirectory = true` токен встраивается в **путь** URL
   (`/bcdn_token=.../videoId/playlist.m3u8`), а не в query-строку.

2. **Не включать IP-привязку** в мобильном приложении. Телефон переключается
   с Wi-Fi на мобильный интернет — IP меняется — воспроизведение падает.
   Ограничение на шеринг аккаунта делаем через счётчик активных сессий.

3. **Подпись загрузки** считается как `SHA256(libraryId + apiKey + expiration + videoId)`,
   срок жизни — минимум 1 час, лучше 6 (большие файлы грузятся долго).

4. **Вебхук приходит без авторизации.** Обязательно сверять `VideoLibraryId`
   с нашим и отвечать 200, иначе Bunny будет слать повторы.

5. **Криптографию для подписи URL не писать руками.** Взять готовый Java-класс
   `TokenSigner` из официального репозитория `BunnyWay/BunnyCDN.TokenAuthentication`
   и положить в `infrastructure/bunny/`.

6. **В PostgreSQL хранятся только метаданные.** Само видео — никогда.
   Обложка не хранится, а собирается по шаблону:
   `https://{cdnHostname}/{bunnyVideoId}/thumbnail.jpg`

```
  src/main/java/uz/streaming/
    catalog/          # сериалы, сезоны, эпизоды, жанры

  store/

  src/features/       # по доменам: videos, series, users, subscriptions

```

## 8. Чего делать НЕ надо

- Не добавлять PATCH-эндпоинты.
- Не отдавать JPA-сущности из контроллеров.
- Не хранить видеофайлы, обложки или бинарные данные в PostgreSQL.
- Не проксировать видео через наш сервер.
- Не коммитить `.env`, ключи, дампы БД.
- Не подключать библиотеки «на будущее», которые сейчас не используются.
- Не писать DRM и оффлайн-скачивание на первом этапе — это отдельная фаза.
