# Локальный бэкенд для тестов с телефона

> Как поднять backend у себя и заставить приложение на телефоне ходить в него,
> пока нет доступа к серверу `uzcasting.site`.

Последнее обновление: 14.08.2026

---

## 1. Зачем

На боевом сервере крутится старая сборка — эндпоинта `POST /api/v1/auth/google` там нет
(проверка — в [GOOGLE_AUTH.md §7](./GOOGLE_AUTH.md)). Пока нет доступа к деплою, вход через
Google проверяется на локальной копии бэкенда.

Заодно это удобнее: база чистая, данные предсказуемые, ничего боевого не заденешь.

---

## 2. Что настроено

| | |
|---|---|
| База | **H2 в памяти**, режим PostgreSQL. Пароль не нужен, Postgres не нужен |
| Данные | 12 анкет + 27 фото, генерируются при старте |
| Профиль Spring | `local` — файл `backend/src/main/resources/application-local.properties` |
| Порт | `8080`, слушает `0.0.0.0` (иначе телефон не достучится) |
| Google client-ids | прописаны в профиле — эндпоинт входа работает |

База живёт только пока запущен процесс. Каждый старт — чистый seed. Это специально:
не накапливается мусор и не нужно ничего чистить.

---

## 3. Запуск

**Бэкенд** — из корня репозитория, не из `backend/`:

```bash
mvn -f backend/pom.xml -DskipTests package
java -jar backend/target/backend-0.0.1-SNAPSHOT.jar --spring.profiles.active=local
```

Почему из корня: `AttachmentServiceImpl` ищет файлы по относительному пути
`backend/files/...`. Из другой директории фото отдаваться не будут.

Признак успеха в логе:

```
LocalSeeder: 12 ta anketa va 27 ta foto yaratildi
```

**Metro:**

```bash
cd mobile
npx expo start --dev-client --host lan
```

---

## 4. Адрес в `.env`

`mobile/.env` → `EXPO_PUBLIC_API_URL` должен указывать на **IP компьютера**, не на
`localhost`: для телефона `localhost` — это он сам.

```
EXPO_PUBLIC_API_URL=http://192.168.x.x:8080
```

Узнать текущий IP:

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.PrefixOrigin -eq 'Dhcp' }
```

**При смене Wi-Fi адрес меняется — надо переписать и перезапустить Metro.** Это самая
частая причина «приложение не грузит данные»: бэк работает, IP устарел.

`EXPO_PUBLIC_*` подставляются в бандл в момент сборки, поэтому правка `.env`
без перезапуска Metro ничего не даёт.

---

## 5. Проверка без телефона

Подставь свой IP — важно проверять именно по нему, а не по `localhost`,
иначе брандмауэр и привязка к адресу остаются непроверенными.

```bash
B=http://192.168.x.x:8080
curl -s -o /dev/null -w "%{http_code}\n" $B/api/v1/casting-user/web              # 200
curl -s -o /dev/null -w "%{http_code}\n" -X POST $B/api/v1/auth/google \
  -H "Content-Type: application/json" -d '{"idToken":"probe"}'                   # 401
```

`401` на неверный токен — правильный ответ: значит client-ids подхватились.
`503` означал бы, что список client ID не задан.

---

## 6. Брандмауэр

Телефону нужны входящие 8080 (бэк) и 8081 (Metro). Правила созданы:

```powershell
Get-NetFirewallRule -DisplayName 'UzCasting dev *'
```

Открыты только для профиля **Private**. Удалить, когда не нужны:

```powershell
Remove-NetFirewallRule -DisplayName 'UzCasting dev *'
```

⚠️ Порты открыты для всей локальной сети, а `SecurityConfig` пускает кого угодно
(см. [API.md](./API.md)). В сети общего пользования локальный бэк виден соседям.
Данные фейковые и живут в памяти, но правила лучше удалять после работы.

## 7. Тестовые данные

Генерирует `backend/src/main/java/com/example/backend/Config/LocalSeeder.java`.

Работает **только** при `app.local.seed=true`, а это свойство есть лишь в профиле
`local`. На сервере его нет, значит сеялка там не запустится даже случайно.

Данные полностью выдуманные. Телефоны, email и параметры фигуры оставлены пустыми
намеренно: на боевом API это персональные данные, отдающиеся без авторизации
(разбор — в [API.md](./API.md)), и тащить их в тестовую базу незачем.

Фото рисуются на лету — градиент из палитры приложения, инициалы и подпись
«TEST MA'LUMOTI». Кладутся в `backend/files/casting/`, имена детерминированные,
поэтому повторный запуск переиспользует те же файлы.

## 7a. Настоящие картинки вместо заглушек

`DevMediaFactory` рисует постеры кодом: градиент, название и подпись
«DEV MA'LUMOTI». Для проверки логики этого хватает, но на скриншотах
приложение выглядит недоделанным — вместо афиши текстовый прямоугольник.

Чтобы подставить настоящие изображения, положите файлы в

```
backend/files/cms-dev/custom/<слаг>.jpg
```

Расширения: `.jpg` · `.jpeg` · `.png` · `.webp`. Слаг — это название
материала в нижнем регистре, где всё, кроме латиницы и цифр, заменено на
дефис (`Owner of My Heart` → `owner-of-my-heart`). Файл нашёлся — сеялка
берёт его и читает реальные размеры; не нашёлся — рисует заглушку как
раньше. **Код менять не нужно, флагов нет.**

Полный список имён с расшифровкой лежит рядом:
`backend/files/cms-dev/custom/README.txt`.

Главные:

| Файл | Что это | Пропорция |
|---|---|---|
| `owner-of-my-heart` · `forgive-me` · `in-the-shadow-of-the-city` · `behind-the-dreams` · `night-of-the-stars` · `open-talk` | постеры контента | 16:9 |
| `a-love-story` · `short-story` | ряд «Reels seriallar» | **9:16** |
| `try-premium` · `summer-sale` · `maintenance-on-aug-21` | баннеры рекламы и объявлений | 16:9 |
| `qalbim-egasi` · `sevgi-qissasi` · `shahar-soyasida` · `coming-soon` | баннеры премьер | 16:9 |

⚠️ После добавления файлов **перезапустите бэкенд**: база H2 в памяти, и
записи о медиа создаются заново при каждом старте.

⚠️ Папка под общим правилом `.gitignore` (`files/`) — изображения могут
быть чужими и в репозиторий не идут.

## 8. Две грабли

**H2-консоль ломает старт.** `spring.h2.console.enabled=true` добавляет отдельный
сервлет, после чего Spring Security не может определить тип паттернов в
`SecurityConfig` и приложение падает: *«cannot decide whether these patterns are
Spring MVC patterns»*. Консоль выключена.

**`open-in-view=false` ломает `/casting-user/web`.** `CastingUser.photos` грузится
лениво и сериализуется уже вне транзакции → `500`. В профиле стоит `true` —
как на сервере по умолчанию. То есть боевой бэкенд тоже зависит от этой настройки;
менять её нужно вместе с бэкендером, а не в локальном конфиге.

---

## 9. Переключение между стендом и боевым сервером

Адрес приходит одним значением, приложение само ничего не угадывает:

| Где | Что задаёт |
|---|---|
| локальный стенд | `mobile/.env` → `EXPO_PUBLIC_API_URL=http://<IP>:8099` |
| сборки EAS (APK) | `eas.json`, поле `env` нужного профиля |
| ничего не задано | `DEFAULT_API_URL` в `src/lib/api.ts` — `http://uzcasting.com` |

Боевой бэкенд развёрнут на **`http://uzcasting.com`** (31.08.2026:
`/api/v1/app/home` отвечает `200`, `/app/me` и `/app/favorites` — `401`,
то есть на месте).

⚠️ **Домен без TLS.** Токен сессии, refresh-токен, номер и код из SMS идут
открытым текстом. Ради этого в сборку добавлены послабления:
`usesCleartextTraffic` для Android (`expo-build-properties`) и исключение
для домена в `NSAppTransportSecurity` для iOS. Как только появится
сертификат — меняется `https` в трёх местах (`api.ts`, `eas.json`,
`app.json`), а послабления **надо убрать**.

⚠️ **Локальность определяется по адресу**, не по `__DEV__`: dev-клиент
подключают и к боевому домену. От этого зависит метка в адресе картинок —
на стенде база в памяти раздаёт те же id другим файлам (`isLocalApi`).

Локальный профиль и сеялку удалять не надо — они не мешают и пригодятся,
когда снова понадобится работать без сервера.
