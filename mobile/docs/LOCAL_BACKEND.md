# Локальный бэкенд для тестов с телефона

> Как поднять backend у себя и заставить приложение на телефоне ходить в него,
> пока нет доступа к серверу `uzcasting.site`.

Последнее обновление: 31.08.2026

---

## 1. Зачем

На боевом сервере крутится **старая сборка**: всего пространства `/api/v1/app/**` там нет.
Проверка на 31.08.2026:

```
POST https://uzcasting.site/api/v1/app/auth/otp/send   → 405, Allow: GET, HEAD
POST https://uzcasting.site/api/v1/auth/google         → 405
GET  https://uzcasting.site/api/v1/app/home            → 200, но это index.html сайта
POST https://uzcasting.site/api/v1/casting-user        → 201 (старый модуль жив)
```

⚠️ Практическое следствие: **приложение против прода не пускает внутрь вообще**. Экран
входа отправляет `POST /api/v1/app/auth/otp/send`, получает 405 без поля `code`, и
`otpErrorKey()` показывает общий текст — *«Kod yuborilmadi, birozdan keyin urinib
ko'ring»*. Выглядит как сбой SMS, хотя SMS тут ни при чём.

Пока нет доступа к деплою, вход и регистрация проверяются на локальной копии бэкенда.
Заодно это удобнее: база чистая, данные предсказуемые, ничего боевого не заденешь.

---

## 2. Что настроено

| | |
|---|---|
| База | **H2 в памяти**, режим PostgreSQL. Пароль не нужен, Postgres не нужен |
| Данные | 12 анкет + 27 фото, генерируются при старте |
| Профиль Spring | `local` — файл `backend/src/main/resources/application-local.properties` |
| Порт | `8080`, слушает `0.0.0.0` (иначе телефон не достучится) |
| Google client-ids | пустые в профиле; вход по номеру от них не зависит |
| SMS | по умолчанию **не отправляется**: код OTP печатается в лог бэкенда. С ключами Eskiz — реальная SMS (см. §4a) |

База живёт только пока запущен процесс. Каждый старт — чистый seed. Это специально:
не накапливается мусор и не нужно ничего чистить.

## 3. Запуск

**Бэкенд** — из корня репозитория, не из `backend/`:

```bash
mvn -f backend/pom.xml -DskipTests package
java -jar backend/target/backend-0.0.1-SNAPSHOT.jar --spring.profiles.active=local
```

Почему из корня: `AttachmentServiceImpl` ищет файлы по относительному пути
`backend/files/...`. Из другой директории фото отдаваться не будут.

Признак успеха в логе:

```
LocalSeeder: 12 ta anketa va 27 ta foto yaratildi
```

**Metro:**

```bash
cd mobile
npx expo start --dev-client --host lan
```

## 4. Адрес в `.env`

`mobile/.env` → `EXPO_PUBLIC_API_URL` должен указывать на **IP компьютера**, не на
`localhost`: для телефона `localhost` — это он сам.

```
EXPO_PUBLIC_API_URL=http://192.168.x.x:8080
```

Узнать текущий IP:

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.PrefixOrigin -eq 'Dhcp' }
```

**При смене Wi-Fi адрес меняется — надо переписать и перезапустить Metro.** Это самая
частая причина «приложение не грузит данные»: бэк работает, IP устарел.

`EXPO_PUBLIC_*` подставляются в бандл в момент сборки, поэтому правка `.env`
без перезапуска Metro ничего не даёт.

## 4a. Вход и регистрация: код приходит в лог, а не в SMS

Телефон + OTP — единственный рабочий способ попасть внутрь приложения (кнопка
Google без client-ids неактивна). На боевом сервере код шлёт Eskiz, но локально
кабинета Eskiz нет, и `POST /otp/send` возвращал бы `503 SMS_NOT_CONFIGURED`.

Поэтому без настроенного кабинета шлюз подменяется:

| Условие | Бин | Что делает |
|---|---|---|
| `eskiz.email` задан (любой профиль) | `EskizSmsClient` | шлёт реальную SMS |
| `eskiz.email` пуст + профиль `local` | `LoggingSmsClient` | пишет код в лог, SMS никуда не уходит |
| `eskiz.email` пуст + сервер | `EskizSmsClient` | честная ошибка `503 SMS_NOT_CONFIGURED` |

⚠️ Раньше выбор был завязан на **профиль** (`EskizSmsClient` имел
`@Profile("!local")`), и локально проверить реальную отправку было нельзя в
принципе — даже с настроенным кабинетом. Теперь решает **конфигурация**.

Свойство, которое защищало прод, при этом сохранено: `LoggingSmsClient`
по-прежнему заперт на `@Profile("local")`, значит на сервере он не создаётся
вообще. Плюс `local` переводит базу на H2 в памяти — включить его в проде
незаметно невозможно.

### Как включить реальную SMS локально

Ключи кладём в `application.properties` **рядом с jar** (в корне репозитория) —
он в `.gitignore` и не попадает внутрь jar:

```properties
eskiz.email=<логин SMS-шлюза>
eskiz.password=<пароль SMS-шлюза>
```

⚠️ Это ключи **SMS-шлюза** (`notify.eskiz.uz`), а не личного кабинета
`my.eskiz.uz`. С паролем от кабинета `/api/auth/login` вернёт 401:
«необходимо использовать логин и пароль только от смс шлюза». Проверить пару
можно одной командой — при верных ключах вернётся токен:

```bash
curl -X POST https://notify.eskiz.uz/api/auth/login -d "email=..." -d "password=..."
```

⚠️ Текст сообщения должен совпадать с шаблоном, одобренным в кабинете
(`GET /api/user/templates`, нужен статус `service`). Иначе Eskiz письмо не
доставит. Если в кабинете одобрен свой никнейм — его нужно прописать в
`eskiz.sms.from`, иначе отправка идёт с общего номера `4546`.

⚠️ Если `eskiz.email` задан, а ключи неверные, локальный стенд остаётся **без
входа вообще**: реальная SMS не уходит, и в лог код тоже не попадает —
`LoggingSmsClient` при заданном `eskiz.email` не создаётся.

Как это выглядит: вводим номер в приложении и смотрим в консоль бэкенда.

```
============================================================
 LOKAL OTP  ·  998901234567
 UzCasting platformasida ro'yxatdan o'tish uchun tasdiqlash kod: 4821
============================================================
```

Этот код вводим на экране OTP. Отдельной «регистрации» нет: `POST /otp/verify`
находит владельца номера или создаёт нового — один эндпоинт на оба сценария.

Кулдаун повторной отправки в профиле снижен со 120 до **5 секунд** — код всё
равно в логе, ждать две минуты незачем. Время жизни кода — 10 минут.

## 5. Проверка без телефона

Подставь свой IP — важно проверять именно по нему, а не по `localhost`,
иначе брандмауэр и привязка к адресу остаются непроверенными.

```bash
B=http://192.168.x.x:8080
curl -s -o /dev/null -w "%{http_code}
" $B/api/v1/casting-user/web   # 200
curl -s -o /dev/null -w "%{http_code}
" $B/api/v1/app/home           # 200

curl -s -X POST $B/api/v1/app/auth/otp/send   -H "Content-Type: application/json" -d '{"phone":"+998901234567"}'
# {"sent":true,"expiresInSeconds":600}
```

Код смотрим в логе бэкенда (§4a) и завершаем вход:

```bash
curl -s -X POST $B/api/v1/app/auth/otp/verify   -H "Content-Type: application/json" -d '{"phone":"+998901234567","code":"4821"}'
# {"access_token":"...","refresh_token":"...","roles":[{"name":"ROLE_USER"}],...}
```

⚠️ В ответе должно быть `"roles":[{"name":"ROLE_USER"}]`. Пустой `roles` означал бы,
что аккаунт создан раньше, чем `AutoRun` успел завести роли. Эта гонка исправлена
(`AutoRun` теперь `@Order(0)`), но если она вернётся — симптом будет именно такой:
войти можно, а всё, что требует прав, закрыто. Молча.

Google-вход проверяется отдельно и только если в профиль вписаны client-ids:

```bash
curl -s -o /dev/null -w "%{http_code}
" -X POST $B/api/v1/auth/google   -H "Content-Type: application/json" -d '{"idToken":"probe"}'         # 401
```

`401` на неверный токен — правильный ответ: значит client-ids подхватились.
`503` означал бы, что список client ID не задан — по умолчанию в профиле так и есть.

## 6. Брандмауэр

Телефону нужны входящие 8080 (бэк) и 8081 (Metro). Правила созданы:

```powershell
Get-NetFirewallRule -DisplayName 'UzCasting dev *'
```

Открыты только для профиля **Private**. Удалить, когда не нужны:

```powershell
Remove-NetFirewallRule -DisplayName 'UzCasting dev *'
```

⚠️ Порты открыты для всей локальной сети, а `SecurityConfig` пускает кого угодно
(см. [API.md](./API.md)). В сети общего пользования локальный бэк виден соседям.
Данные фейковые и живут в памяти, но правила лучше удалять после работы.

## 7. Тестовые данные

Генерирует `backend/src/main/java/com/example/backend/Config/LocalSeeder.java`.

Работает **только** при `app.local.seed=true`, а это свойство есть лишь в профиле
`local`. На сервере его нет, значит сеялка там не запустится даже случайно.

Данные полностью выдуманные. Телефоны, email и параметры фигуры оставлены пустыми
намеренно: на боевом API это персональные данные, отдающиеся без авторизации
(разбор — в [API.md](./API.md)), и тащить их в тестовую базу незачем.

Фото рисуются на лету — градиент из палитры приложения, инициалы и подпись
«TEST MA'LUMOTI». Кладутся в `backend/files/casting/`, имена детерминированные,
поэтому повторный запуск переиспользует те же файлы.

## 7a. Настоящие картинки вместо заглушек

`DevMediaFactory` рисует постеры кодом: градиент, название и подпись
«DEV MA'LUMOTI». Для проверки логики этого хватает, но на скриншотах
приложение выглядит недоделанным — вместо афиши текстовый прямоугольник.

Чтобы подставить настоящие изображения, положите файлы в

```
backend/files/cms-dev/custom/<слаг>.jpg
```

Расширения: `.jpg` · `.jpeg` · `.png` · `.webp`. Слаг — это название
материала в нижнем регистре, где всё, кроме латиницы и цифр, заменено на
дефис (`Owner of My Heart` → `owner-of-my-heart`). Файл нашёлся — сеялка
берёт его и читает реальные размеры; не нашёлся — рисует заглушку как
раньше. **Код менять не нужно, флагов нет.**

Полный список имён с расшифровкой лежит рядом:
`backend/files/cms-dev/custom/README.txt`.

Главные:

| Файл | Что это | Пропорция |
|---|---|---|
| `owner-of-my-heart` · `forgive-me` · `in-the-shadow-of-the-city` · `behind-the-dreams` · `night-of-the-stars` · `open-talk` | постеры контента | 16:9 |
| `a-love-story` · `short-story` | ряд «Reels seriallar» | **9:16** |
| `try-premium` · `summer-sale` · `maintenance-on-aug-21` | баннеры рекламы и объявлений | 16:9 |
| `qalbim-egasi` · `sevgi-qissasi` · `shahar-soyasida` · `coming-soon` | баннеры премьер | 16:9 |

⚠️ После добавления файлов **перезапустите бэкенд**: база H2 в памяти, и
записи о медиа создаются заново при каждом старте.

⚠️ Папка под общим правилом `.gitignore` (`files/`) — изображения могут
быть чужими и в репозиторий не идут.

## 8. Две грабли

**H2-консоль ломает старт.** `spring.h2.console.enabled=true` добавляет отдельный
сервлет, после чего Spring Security не может определить тип паттернов в
`SecurityConfig` и приложение падает: *«cannot decide whether these patterns are
Spring MVC patterns»*. Консоль выключена.

**`open-in-view=false` ломает `/casting-user/web`.** `CastingUser.photos` грузится
лениво и сериализуется уже вне транзакции → `500`. В профиле стоит `true` —
как на сервере по умолчанию. То есть боевой бэкенд тоже зависит от этой настройки;
менять её нужно вместе с бэкендером, а не в локальном конфиге.

## 9. Переключение между стендом и боевым сервером

Адрес приходит одним значением, приложение само ничего не угадывает:

| Где | Что задаёт |
|---|---|
| локальный стенд | `mobile/.env` → `EXPO_PUBLIC_API_URL=http://<IP>:8099` |
| сборки EAS (APK) | `eas.json`, поле `env` нужного профиля |
| ничего не задано | `DEFAULT_API_URL` в `src/lib/api.ts` — `https://uzcasting.com` |

Боевой бэкенд развёрнут на **`https://uzcasting.com`** (02.09.2026:
`/api/v1/app/home` отвечает `200` и уже с содержимым, `/app/me` и
`/app/favorites` — `401`, картинки `/app/media/{id}/raw` — `200`).

⚠️ **Только `https`.** 30.08.2026 домену выпустили сертификат (GlobalSign,
до 17.03.2027), и nginx отвечает на `http://` редиректом `301`. Это не
«просто небезопасно»: GET редирект переживает, а POST — нет, клиент
повторяет его как GET и без тела. На `http://` вход перестаёт работать
молча. Прежние послабления (`usesCleartextTraffic`, исключение в
`NSAppTransportSecurity`) из релизных сборок убраны — открытый http
остался только у профиля `development`, для стенда по LAN (`app.config.js`).

### ⚠️ Цепочка сертификата: Android строже браузера (03.09.2026)

Симптом: приложение НЕ ходит на сервер вообще — `ERR_NETWORK`, а внутри
`javax.net.ssl.SSLHandshakeException`. При этом браузер на том же телефоне
открывает `https://uzcasting.com/api/v1/app/home` и показывает JSON, и с
рабочей машины всё исправно.

Причина: сервер отдавал цепочку, которая заканчивалась корнем **GlobalSign
Root R46** (2019 год). Chrome носит собственное хранилище корней, поэтому у
него всё работало, а приложение пользуется СИСТЕМНЫМ хранилищем Android — и
там этого корня может не быть.

Лечится на сервере, без переоформления сертификата: последним в цепочку
кладётся **кросс-сертификат** — тот же R46, но подписанный старым корнем
`GlobalSign Root CA - R3`, который есть на Android много лет.

```sh
curl -sS -o /tmp/r3r46.crt https://secure.globalsign.com/cacert/r3r46cross2019.crt
openssl x509 -inform DER -in /tmp/r3r46.crt -out /tmp/r3r46.pem
awk '/BEGIN CERTIFICATE/{c++} c<=2' /etc/nginx/ssl/certificate.crt > /tmp/chain-new.pem
cat /tmp/r3r46.pem >> /tmp/chain-new.pem
cp /tmp/chain-new.pem /etc/nginx/ssl/certificate.crt
nginx -t && systemctl reload nginx
```

Проверка снаружи — последняя строка должна быть `Root CA - R3`, а не
самоподписанный R46:

```bash
openssl s_client -connect uzcasting.com:443 -servername uzcasting.com -showcerts   </dev/null 2>/dev/null | grep -E '^ [0-9]+ s:|^   i:'
```

⚠️ **Проверять надо на телефоне, а не в браузере.** Браузер здесь даёт
ложное «всё в порядке»: он судит по своему хранилищу корней. Это же
относится и к `curl` с рабочей машины.

⚠️ **Дежурная проверка при смене сертификата.** Продление или переезд на
другого поставщика вернёт проблему, если цепочку соберут заново без
кросс-сертификата, а увидим мы это только на устройствах.

⚠️ **Локальность определяется по адресу**, не по `__DEV__`: dev-клиент
подключают и к боевому домену. От этого зависит метка в адресе картинок —
на стенде база в памяти раздаёт те же id другим файлам (`isLocalApi`).

Локальный профиль и сеялку удалять не надо — они не мешают и пригодятся,
когда снова понадобится работать без сервера.
